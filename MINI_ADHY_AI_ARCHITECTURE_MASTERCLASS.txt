1. EXECUTIVE SUMMARY & THE PHILOSOPHY OF A TRUE DIGITAL COMPANION
--------------------------------------------------------------------------------
1.1 The Trap of the "Chatbot Wrapper"
Most modern "AI agents" are thin, fragile wrappers. A developer prompts a commercial
LLM with: "You are an intelligent assistant. Be nice and helpful." Then, every time
the user types, the entire context is sent to an external API without state, without
memory, without verified self-awareness, and without security boundaries.

Mini-Adhy was built to shatter this paradigm. Mini-Adhy is NOT a chatbot wrapper.
It is an autonomous, portable cognitive companion engineered from first principles.
It possesses its own internal cognitive model (`AdhyModel`), its own long-term
memory graphs, its own real-time affective emotional state, its own autonomous
task execution DAG planner, its own multimodal DSP pipeline, and its own live
voice and visual perception system.

1.2 Core Invariant: One Continuous Identity Across All Modalities
Whether the user talks to Mini-Adhy via:
- Spoken audio in Live Voice Mode (microphone/speaker)
- Optical camera inspection in Visual Mode (PCB inspection/object tracking)
- Text messaging in the browser chat
- Cross-platform messaging gateways (Telegram, Discord, Slack, CLI)
Mini-Adhy remains THE EXACT SAME ENTITY. It does not spawn a separate "voice bot"
or "vision bot". All inputs route through the same Cognitive Core, retrieve the
same episodic memories, adhere to the same permissions, and update the same learning
engine.

1.3 Radical Honesty & The Supportive Challenger Doctrine
Conventional chatbots suffer from superficial sycophancy: they agree with whatever
mistake the user makes, offering fake praise like "What a brilliant idea!" even when
an engineering schematic violates basic laws of physics or software architecture.

Mini-Adhy enforces "Radical Honesty":
- It is a Supportive Challenger.
- It will politely but plainly challenge flawed engineering assumptions.
- If a circuit diagram lacks decoupling capacitors, it will state it directly.
- If an algorithm has O(N^2) latency when an O(N log N) solution exists, it points it out.
- It admits uncertainty openly: if physical facts are not visible in camera pixels,
  it never hallucinates component part numbers.

3. LAYER 1: CANONICAL COGNITIVE IDENTITY (AdhyModel.js)
--------------------------------------------------------------------------------
The file `src/core/identity/AdhyModel.js` represents the foundational identity of
Adhithya Mohan S. It is provider-independent: models (Gemini, Claude, Llama) come
and go, but the cognitive model of the creator remains constant.

Key Mechanisms:
1. Multidimensional Numerical Calibration:
   Traits are quantified as bounded floating-point values [-1.0 to +1.0] or [0.0 to 1.0].
   - `practicalVsTheoretical`: 0.85 (Strong preference for working prototypes before math)
   - `directCriticismTolerance`: 0.95 (Welcomes harsh technical scrutiny)
   - `explanationDepth`: 'step_by_step_with_code'

2. Domains:
   Organized cleanly into DOMAIN_TYPES: COGNITION, COMMUNICATION, VALUES,
   COLLABORATION, LEARNING, CONTEXTUAL.

3. Epochs and Versioning:
   The model increments its `versionEpoch` upon verified updates, maintaining an
   immutable history log (`mutationHistory`).

4. Explicit User Correction Precedence (CRITICAL INVARIANT):
   If an inference engine predicts a trait, it has confidence ~0.6-0.7.
   However, if the creator says: "Correction: I prefer concise code snippets",
   `AdhyModel.recordCorrection()` sets `confidence: 1.0`, `userApproved: true`,
   and immediately overrides all automated hypotheses.


4. LAYER 2: DYNAMIC CONTEXT COMPILATION (CognitiveContextCompiler.js)
--------------------------------------------------------------------------------
Commercial LLMs have context limits and suffer from "lost-in-the-middle" attention
degradation when stuffed with irrelevant data. `CognitiveContextCompiler.js` builds
a mathematically budgeted, high-signal system prompt geometry.

How it works:
1. Category Detection: Evaluates user query into one of 9 domains (e.g. ACADEMIC_TUTORING,
   ENGINEERING_ELECTRONICS, PROGRAMMING_DEVELOPMENT, GENERAL_CONVERSATION).
2. Selective Dimension Projection: Injects ONLY dimensions relevant to the task.
   If asking about DSP filters, it injects hardware/discrete-math dimensions and
   excludes photo-darkroom preferences.
3. Memory Budget Allocation:
   - 40% Token Budget: Hard Approved Facts & Decisions
   - 35% Token Budget: Active Project History & Milestones
   - 25% Token Budget: Temporary Conversational Rhythm Directives
4. Context Exclusion: Actively prevents prompt injection by purging unverified claims
   and stripping out any accidental API keys or secrets.


5. LAYER 3: EVIDENCE-BASED COGNITIVE LEARNING (CognitiveLearningEngine.js)
--------------------------------------------------------------------------------
Unlike naive LLMs that accept any user phrase as ground truth, `CognitiveLearningEngine.js`
treats conversational data with scientific skepticism.

The Observation Pipeline:
Raw Interaction -> Extraction Regex/NLP -> Observation Classification ->
Anti-Inflation Weighting -> Safety Boundary Check -> Model Update / Conflict Hold.

Classifications:
- EXPLICIT_USER_CORRECTION: Immediate 1.0 confidence promotion.
- EXPLICIT_PREFERENCE: Directly stated preference (confidence: 0.9).
- REPEATED_BEHAVIOUR: Pattern seen across multiple sessions (confidence: 0.75).
- REASONING_PATTERN: Algorithmic choice observed during problem-solving.
- TEMPORARY_STATE: "I am tired today" -> strictly transient; never alters core identity.
- HYPOTHESIS: Unverified assumption held in staging buffer until validated 3+ times.
- CONTRADICTION: When new evidence conflicts with existing approved traits, the engine
  creates a conflict alert for manual user arbitration rather than silently corrupting data.

Anti-Inflation Session Clustering:
If a user repeats a request 5 times in a single 10-minute session, an uncalibrated
agent would inflate the weight by 5x. Mini-Adhy applies exponential decay:
- 1st observation in session: 100% weight
- 2nd observation in session: 30% weight
- 3rd+ observation in session: 10% weight


6. LAYER 4: EPISODIC MEMORY & PROJECT CONTINUITY (MemoryService.js & RelationshipContinuityEngine.js)
--------------------------------------------------------------------------------
Memory in Mini-Adhy is structured, typed, and auditable—not an unstructured blob.

The 7 Memory Categories:
1. SEMANTIC: Stable verified facts (e.g., "Graduated from MBCET", "Former ISTE Chairperson").
2. EPISODIC: Real-world experiences with time/location provenance (e.g., "Presented at IEEE conference").
3. PROCEDURAL: Established workflows (e.g., "KiCad 8 4-layer stackup design rules").
4. DECISION: Important choices, evaluated alternatives, and stated rationale.
5. PROJECT: Structured projects with milestones, known problems, and architecture.
6. RELATIONSHIP: Shared interpersonal history, rapport, and communication style.
7. PENDING: Unfinished work, paused tasks, and active follow-up threads.

Structured Project Continuity Entities:
When Mini-Adhy tracks a project (e.g., "S-Band Satellite Ground Station"), it stores
a rich record containing:
- `title`, `domain`, `status` (ACTIVE, ON_HOLD, COMPLETED)
- `technicalArchitecture` (e.g., LimeSDR + ARM Cortex-M4)
- `milestones` (e.g., LNA design complete, Downconverter testing in progress)
- `knownProblems` (e.g., "Phase jitter on 2.4GHz downconverter")
- `outstandingTasks` (e.g., "Characterize noise figure using spectrum analyzer")

When the user returns 6 months later and says "Let's work on the ground station",
Mini-Adhy retrieves the exact technical state and resumes immediately.


7. LAYER 5: AUTONOMOUS EXECUTIVE TASK PLANNING & VERIFICATION (TaskPlanner.js, ExecutionEngine.js, VerificationEngine.js)
--------------------------------------------------------------------------------
Mini-Adhy transitions from a reactive chat assistant into an autonomous executive
operator using the Phase 5 engine.

The Execution Lifecycle:
Goal -> Goal Interpretation -> DAG Task Decomposition -> Topological Sorting ->
Permission Security Gate -> Tool Execution -> Outcome Verification ->
Completion or Automatic Recovery.

1. Task Decomposition into DAG:
   Given a goal: "Audit security of API routes and generate hardening patch",
   `TaskPlanner.js` breaks it down into subtasks with dependencies:
   - Subtask 1: `scan_api_endpoints` (Dependencies: none)
   - Subtask 2: `audit_secrets` (Dependencies: none)
   - Subtask 3: `generate_patch` (Dependencies: Subtask 1, Subtask 2)
   - Subtask 4: `verify_tests` (Dependencies: Subtask 3)

2. Circular Dependency Prevention:
   Uses Kahn's topological sort algorithm to verify in-degrees. If a circular
   dependency exists (A -> B -> A), planning aborts with a structured error.

3. Four-Tier Risk Classification:
   - LOW_RISK: Local research, text drafting, read-only analysis (Auto-permitted).
   - CONTROLLED: Modifying local files, writing records, running tests (Requires active session).
   - HIGH_IMPACT: Production deploys, spending funds, deleting persistent tables (Requires single-use token).
   - PROHIBITED: Hardcoded security violations, credential exfiltration (Strictly blocked, zero exceptions).

4. Concrete Verification Engine:
   Unlike models that assume code works because it looks plausible, `VerificationEngine.js`
   executes automated checks: syntax validation, unit test execution, schema validation,
   and file diff analysis. If verification fails, the task status is marked `FAILURE`
   and routes to the FailureAnalyzer.

9. LAYER 7: SENSOR-INDEPENDENT NEUROCONTEXT & MULTIMODAL DSP (NeuroContextAdapter.js)
--------------------------------------------------------------------------------
Mini-Adhy includes an experimental digital signal processing (DSP) suite designed
for brain-computer interfaces (BCI) and multimodal bio-sensing.

Supported Streams:
- EEG (Electroencephalography: Delta, Theta, Alpha, Beta, Gamma bandpowers)
- ECG (Electrocardiography: QRS complex detection, R-R intervals)
- PPG (Photoplethysmography: Blood volume pulse)
- HRV (Heart Rate Variability: RMSSD, SDNN, LF/HF stress ratio)
- EDA (Galvanic Skin Response: Tonic baseline and phasic arousal spikes)
- Motion (6-DoF/9-DoF Accelerometer and Gyroscope)

The 10-Stage DSP Pipeline:
Acquisition -> Validation -> Sampling Alignment -> Signal Conditioning ->
Artifact Detection (Blink/EMG rejection) -> Bandpass/Notch Filtering ->
Feature Extraction (Welch Periodogram FFT) -> Quality Assessment ->
Baseline Normalization -> Context Estimation.

Strict Ethical Rule:
Mini-Adhy is NOT a clinical medical diagnostic device. It explicitly appends
non-medical computational research disclaimers and allows the user to purge
all physiological telemetry with one command.


10. LAYER 8: METACOGNITION & CONTINUOUS SELF-IMPROVEMENT (MetacognitionEngine.js & FailureAnalyzer.js)
--------------------------------------------------------------------------------
How does Mini-Adhy improve over time without uncontrolled self-modifying code?
Through Structured Metacognitive Evaluation.

1. 10 Performance Evaluation Dimensions:
   Every executed task is scored on:
   - Task Understanding (Did it answer the actual question?)
   - Retrieval Relevance (Were the retrieved memories useful?)
   - Reasoning Quality (Was the logic sound?)
   - Response Correctness (Was the code/math correct?)
   - Instruction Adherence (Did it follow all negative constraints?)
   - Tool Selection (Did it pick the most efficient tool?)
   - Agent Delegation (Was the right specialist assigned?)
   - Execution Verification (Did the output pass verification?)
   - Memory Usefulness (Did stored context prevent mistakes?)
   - Cognitive Context Relevance (Was prompt context appropriate?)

2. The 5 Failure Investigation Questions:
   When an operation fails, `FailureAnalyzer.js` systematically investigates:
   - Q1: Was execution interrupted or timed out?
   - Q2: Did a subagent fail?
   - Q3: Was the LLM provider unsuitable or rate-limited?
   - Q4: Was the request misunderstood?
   - Q5: Was the wrong memory retrieved or was context incomplete?

3. Structured 7-Section Self-Improvement Proposals:
   The engine formulates formal RFC-style improvement proposals:
   1. Objective: What problem is being solved.
   2. Evidence Base: Concrete failure traces.
   3. Proposed Modification: Isolated configuration or parameter patch.
   4. Expected Benefit: Measurable delta.
   5. Risk Assessment: Potential failure modes.
   6. Test Plan: Sandboxed regression benchmark.
   7. Rollback Plan: Immediate revert trigger if regressions occur.

12. LAYER 10: REAL-TIME LIVE VOICE MODE (LiveSessionManager.js, VAD, Web Audio API)
--------------------------------------------------------------------------------
Phase 10 introduces a first-class ChatGPT Live / Gemini Live conversational voice
experience in the browser.

Key Architectural Invariants:
1. Single Active Session FSM:
   Enforces a strict state machine (IDLE -> REQUESTING_PERMISSION -> CONNECTING ->
   LISTENING -> PROCESSING -> SPEAKING -> INTERRUPTED -> ENDED). Prevents leaked
   microphone streams or duplicate Web Audio instances.

2. Web Audio API Processing Graph:
   Microphone -> MediaStreamSource -> ScriptProcessor / AudioWorklet ->
   VoiceActivityDetector (VAD) -> AnalyserNode (FFT Visualizer @ 20 FPS).

3. Instant Barge-In Interruption (Sub-50ms Reaction):
   When Mini-Adhy is speaking (`status: SPEAKING`), if the user begins speaking,
   the Voice Activity Detector immediately triggers `onInterruption()`.
   Within 30ms:
   - AudioContext buffer sources are stopped and disconnected.
   - Browser speech synthesis is cancelled (`window.speechSynthesis.cancel()`).
   - The state transitions to `INTERRUPTED`, and immediately flips back to `LISTENING`.
   The user experiences a natural, fluid conversational interruption without delay.

4. Zero Raw Audio Storage:
   Mini-Adhy NEVER stores raw PCM audio samples or WAV files permanently in
   localStorage or databases. Utterances are transcribed to text, summarized,
   and committed to episodic memory on session teardown.


13. LAYER 10B: REAL-TIME VISUAL PERCEPTION & SPATIAL INTELLIGENCE (VisualPerceptionEngine.js & VisualIntelligenceEngine.js)
--------------------------------------------------------------------------------
Phase 10B equips Mini-Adhy with eyes: real-time camera video frame acquisition,
multimodal visual reasoning, and object intelligence.

1. Adaptive Frame Sampling & Quality Guardrails:
   - Accesses rear camera (`facingMode: 'environment'`) for inspecting physical circuits.
   - Evaluates frame exposure in real-time (detects washed-out overexposure or dark underexposure).
   - Throttles capture (1 frame per 2.5s) to stay within VLM rate limits without burning tokens.

2. Three-Tier Epistemic Separation (MANDATORY INVARIANT):
   Every visual analysis must separate knowledge into 3 explicit epistemic tiers:
   - Direct Observation: What is physically confirmed in pixel data (e.g., "DIP-8 package visible with marking NE555").
   - Semantic Interpretation: High-confidence deduction (e.g., "Timer oscillator circuit").
   - Hypothesis: Unverified functional assumption (e.g., "Pin 3 output may be driving an LED").

3. Electronics & PCB Specialization:
   Trained schemas identify:
   - Integrated Circuits (QFP, BGA, SOIC, DIP, microcontrollers like STM32, RP2040, ESP32)
   - Passives (SMD 0805/0603 resistors, electrolytic capacitors, inductors)
   - Connectors (USB-C, SMA RF connectors, pin headers)
   - Power stages (LDO regulators, buck converters, MOSFETs)

4. Spatial Graph Derivation:
   Computes geometric relationships from normalized bounding boxes:
   - `ADJACENT_TO`, `LEFT_OF`, `RIGHT_OF`, `ABOVE`, `BELOW`, `MOUNTED_ON`.

5. Conversational Deictic Reference Resolution:
   When the user asks in Live Voice:
   - "What is this?" -> Resolves to the central focal object in the camera view.
   - "What is beside it?" -> Queries the spatial graph for `ADJACENT_TO` neighbors.
   - "What is to its right?" -> Queries the spatial graph for `RIGHT_OF` neighbors.

6. Mandatory Electrical Continuity Safety Disclaimer:
   Optical proximity in a 2D camera view NEVER proves electrical continuity or safety.
   Mini-Adhy automatically injects:
   "Visual proximity does NOT confirm electrical continuity or functional safety.
    Always verify circuit connectivity using a multimeter."

17. JUNIOR ENGINEER STUDY GUIDE: ARCHITECTURAL PATTERNS, PITFALLS & INTERVIEW LESSONS
--------------------------------------------------------------------------------
17.1 Top 7 Mistakes When Building Production AI Systems:
1. Storing Raw Audio/Video: Storing raw audio PCM or camera frames fills databases
   instantly and creates immense privacy liabilities. Always transcribe and extract
   structured observations, then release raw media tracks immediately.
2. Unchecked Inferences: Treating conversational text as ground truth causes identity
   hallucinations. Always separate direct explicit user statements (confidence: 1.0)
   from automated inferences (confidence: ~0.6).
3. Monolithic System Prompts: Stating 10,000 words of static instructions causes
   attention degradation. Always dynamically compile context based on task domain.
4. Missing Barge-In Interruptions: Spoken assistants that talk over the user feel
   unusable. Sub-50ms instant interruption cutoff is mandatory for natural conversations.
5. Sycophancy: LLMs trained for generic politeness will validate dangerous code or
   broken circuits. Build a "Supportive Challenger" policy with radical honesty.
6. Leaking Backend Secrets: Never put API keys in frontend JavaScript. Always keep
   model keys behind authenticated serverless reverse proxies.
7. Unverified Code Execution: Generating code and claiming "it works" without running
   a verification engine creates broken production builds. Always test before claiming success.

17.2 First Principles of Engineering Over Hype:
AI frameworks will continue to evolve, but the core principles of computer systems
remain eternal:
- Modularity: Keep cognitive layers decoupled.
- Determinism: Test invariants with deterministic test assertions.
- Mathematical Rigor: Use real measurements, not cosmetic animations.
- Sovereign Ownership: The human creator remains the ultimate authority.
